Auto routing

Pick Auto in Factory for normal sessions, or the Auto · Orchestrator / Worker / Validator models for Mission roles. The first message of each session is classified by a fast model, and that session then stays on the model chosen for its task type and role. Each role has its own backup.

Balanced routing

Each new Auto session uses whichever model in its pool (the task type's model plus its backups) has the most subscription quota left, so heavy coding drains every plan evenly. When every subscription in the pool is below the threshold, the session goes to your pay-per-token overflow models.

Factory modes

Which model Factory uses for normal sessions, spec mode, and each Mission role. Applying writes Factory's settings (a backup is saved first). "Factory default" lets Factory inherit the session model.

Backup models

When a model is out of quota, the same request is retried on the next model in its list, left to right. Exhausted models are skipped until they cool down.
